## 1. ความปลอดภัยก่อนเริ่มงาน

- [ ] เปิดหน้าเว็บในหน้าต่างไม่ระบุตัวตนและยืนยันว่าเห็นเฉพาะหน้าเข้าสู่ระบบ ไม่มี Dashboard, ตารางผู้ป่วย หรือเมนูระบบอยู่ด้านหลัง
- [ ] ตรวจว่าหน้า Login มีอีเมล, รหัสผ่าน, ปุ่มแสดง/ซ่อนรหัสผ่าน, ลงทะเบียน และลืมรหัสผ่าน
- [ ] ทดสอบรหัสผ่านผิดด้วยบัญชีทดสอบ 1 ครั้ง และยืนยันว่าข้อความแจ้งเตือนไม่เปิดเผยรายละเอียดเชิงเทคนิค
- [ ] ยืนยันว่าไม่มี `service_role` key, access token หรือรหัสผ่านอยู่ใน source code, Console หรือเอกสารที่เผยแพร่

## 3. ทดสอบข้อมูลแบบปลอดภัย

- [ ] ใช้ไฟล์ Excel ทดสอบที่ไม่มีข้อมูลระบุตัวบุคคล และเก็บไฟล์ต้นฉบับไว้ในที่จัดเก็บของโรงพยาบาล
- [ ] นำเข้าครั้งแรก: ตรวจจำนวนรายการ, โรค, วันเริ่มป่วย, พื้นที่ และสถานะ sync กลาง
- [ ] นำเข้าไฟล์เดิมซ้ำ: ตรวจว่าไม่มีรายการส่วนกลางซ้ำ
- [ ] เปิดอย่างน้อย 1 case, แก้ไขข้อมูลทดสอบ, และตรวจ Sweet Alert สถานะสำเร็จ
- [ ] สร้าง PDF อย่างน้อย 1 รายงานและตรวจโลโก้, ชื่อโรงพยาบาล, วันที่พิมพ์ และเนื้อหาตรงกับหน้าจอ
- [ ] ลบหรือทำเครื่องหมายข้อมูลทดสอบตามขั้นตอนที่ ADMIN อนุญาต แล้วตรวจว่ามี Audit Log

## 4. การเชื่อมต่อและเหตุขัดข้อง

- [ ] ตัดการเชื่อมต่อชั่วคราวขณะทำรายการทดสอบ และยืนยันว่าเห็นข้อความแจ้งสถานะที่อ่านเข้าใจได้
- [ ] เชื่อมต่อกลับ แล้วรีเฟรช/ทำซ้ำรายการตามคำแนะนำ โดยไม่เกิดข้อมูลซ้ำ
- [ ] ตรวจ Supabase Dashboard: API errors, Database logs และ Audit Log ของรายการทดสอบ
- [ ] ยืนยันว่าการแจ้งเตือนไม่แสดงข้อมูลผู้ป่วยหรือ token

## 5. อนุมัติเปิดใช้งาน

- [ ] ผ่านทุกข้อ หรือบันทึกข้อยกเว้นและผู้รับผิดชอบไว้ด้านล่าง
- [ ] ADMIN ได้ตรวจการจัดการบัญชีจริง 1 รอบ โดยไม่ส่งรหัสผ่านให้ผู้ใด
- [ ] ผู้รับผิดชอบมีสำเนาไฟล์ Excel ต้นฉบับและรายงาน export ตามรอบปฏิบัติงาน
- [ ] รับทราบว่า Free Plan ไม่มี scheduled backup; ปฏิบัติตามแผนสำรองใน `PRODUCTION-RUNBOOK.md`
